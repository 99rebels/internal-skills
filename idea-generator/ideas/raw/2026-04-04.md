# Skill Improvement Ideas — 2026-04-04

Note: These are improvements to existing published skills, not original skill ideas.

## 🔵 Gmail Body Snippet Preview
What it is: Fetch first ~200 chars of email body so users can see context without opening Gmail. Currently only shows subject + sender.
Origin: Reviewing [rebels-gmail-checker](/home/rianoleary/.openclaw/workspace/skills/gmail-checker) — output is minimal, users likely want a snippet to decide if an email matters.
Open questions: Token cost of fetching body for every email? Should it be opt-in via config flag?
Status: researched

## 🔵 Gmail Multi-Account Support
What it is: Allow checking multiple Gmail accounts by supporting credential files with a naming pattern (e.g. `gmail-work.json`, `gmail-personal.json`).
Origin: Reviewing gmail-checker — single account limitation obvious for anyone with work + personal email.
Open questions: How to select which account? CLI flag, config, or separate setup?
Status: researched

## 🔵 Gmail Send/Reply Action
What it is: Add ability to send quick replies or compose emails from the agent. "Reply to Sarah's email saying I'll be there" or "Send an email to X about Y".
Origin: Reviewing gmail-checker — read-only is limiting. Being able to reply from Slack/Discord would be high value.
Open questions: OAuth scope expansion needed? How to handle drafts vs sends?
Status: researched

## 🔵 GitHub PR and Release Tracking
What it is: Track open PRs, recent releases, and contributor activity alongside current stars/forks/commits metrics.
Origin: Reviewing [github-growth-tracker](/home/rianoleary/.openclaw/workspace/skills/github-growth-tracker) — current metrics are surface-level, PRs and releases are better engagement signals.
Open questions: API cost for PR listing? Worth adding as optional `--include-prs` flag?
Status: researched

## 🔵 GitHub Digest JSON Output
What it is: Add `--json` flag to the `digest` command for structured output, matching what gmail-checker already does.
Origin: Reviewing github-growth-tracker — currently text-only output, inconsistent with gmail-checker's dual format approach.
Open questions: Minimal effort, just needs a `format_json_digest()` function.
Status: researched

## 🔵 GitHub Webhook Integration
What it is: Receive instant push notifications for stars/forks/new issues instead of polling. Set up GitHub webhooks that trigger a fetch.
Origin: Reviewing github-growth-tracker — cron-based polling is fine for daily digests but misses real-time events.
Open questions: Requires a public endpoint. Feasible on a Pi? Maybe overkill for now?
Status: researched

## 🔵 Skill Polisher Batch Mode
What it is: Polish multiple skills at once — point at a skills directory and polish every SKILL.md found.
Origin: Reviewing [rebels-skill-polisher](/home/rianoleary/.openclaw/workspace/skills/skill-polisher) — we have 5+ skills, polishing one at a time is tedious.
Open questions: How to handle approval? Polish all then present batch diff?
Status: researched

## 🔵 Skill Polisher Non-SKILL.md Files

Origin: Reviewing skill-polisher — currently only touches SKILL.md, but reference files can also be inconsistent or poorly formatted.

Status: researched

## 🔵 Portability Checker Auto-Publish Fix

Origin: Reviewing [agent-portability-checker](/home/rianoleary/.openclaw/workspace/skills/agent-portability-checker) — current workflow is fix → manually verify → manually publish. Could streamline.
